01 · CONCEPTS

先把四個名詞分清楚

VID

Voltage Identification

代表 CPU 想要的「電壓代碼／目標設定值」。它不是量測出來的電壓值。

SVID

Serial Voltage Identification

CPU 與 VR Controller 交換電壓要求、狀態資訊的序列通訊介面。

VR Controller

Voltage Regulator Controller

負責根據要求及回授，產生 PWM 控制訊號、調整輸出並做保護。

VRM / VR

Voltage Regulator Module / Regulator

包含 Controller、Power Stage、電感、電容及回授等，用電力電路真正供電給 CPU。

白話記法：CPU 像客人，說「我要這個電壓」；SVID 像點餐系統；VR Controller 像廚房主管；Power Stage、電感與電容才是實際做出供電的廚房。
02 · SYSTEM ARCHITECTURE

CPU 到 VRM：哪條是「訊號」？哪條是「電」？

請先注意兩個不同方向：控制命令從 CPU 去 VR Controller；真正的 Vcore 電流則從 VRM 流進 CPU。

示意架構，不是 D-1713NT 的特定電路圖。VRM 實際配置需以所用 COM 模組原理圖為準。
容易搞錯：SVID 不負責輸送 CPU 的工作電流；VR Controller 本身也不是把大電流直接供給 CPU 的主要功率元件。後面還需要 Power Stage、電感與電容。
03 · THREE SIGNALS

SVID 有哪三條訊號？從誰到誰？

在典型 Intel SVID 系統中，CPU 是通訊主端，VR Controller 是受控端。訊號名稱依平台略有不同，常見是 SVID_CLK、SVID_DATA、SVID_ALERT#。

訊號主要方向用處白話記憶
SVID_CLKCPU → VR Controller提供序列傳輸節拍，讓雙方在時脈下交換資訊「照這個節奏對話」
SVID_DATACPU ↔ VR ControllerCPU 發送 VID 指令，VR 回覆狀態／資料「我們說話的內容」
SVID_ALERT#VR Controller → CPUVR 通知狀態變化，例如完成狀態或故障事件；實際用途依協定「有事要回報！」
Clock 與 Data 在常見 Intel SVID 設計採開汲極（open-drain）方式，需依平台規範配置適合的上拉及訊號電壓。
面試考點：不要把 SVID 當成 I²C，也不要把 Intel 的 SVID 跟 AMD 的 SVI2／SVI3 混為一談。它們都是電壓管理介面，但協定不同。
04 · INSIDE THE VRM

VR Controller 到底在控制什麼？

Controller 做決策

解析電壓要求、產生 PWM、讀回授、保護過流／過壓／過熱，必要時回報警訊。

Power Stage 真正出力

把 12V 經由高速切換及 LC 濾波變成 CPU 需要的低壓、大電流；多相並聯可分攤負載。

控制核心：VR Controller 比較「CPU 要的目標」與「回授量到的輸出」，再調整 PWM。負載瞬間從輕載變重載時，它還需要兼顧暫態響應（Transient Response）、Load-line、穩定度與保護。

一個工程師必懂的觀念：CPU 要求某個 VID，不代表萬用表量到的 Vcore 一定與之完全相同；負載線（load-line）、電流、量測位置與回授設定都會影響實際電壓。
05 · POWER SEQUENCING

開機時，SVID 是第一個出現的嗎？

不一定，通常不是。啟動前需要先有控制器可工作的供電、啟用條件和必要平台電源；控制器可能依預設的啟動設定建立初始電壓。之後 CPU／SoC 才在適當階段開始 SVID 通訊、要求不同運行電壓。

*PGOOD 時序位置、產生者、先後條件都依晶片和整個平台 power sequence 而定，圖不可直接當作測試規格。
供電先到位載板、模組的主電源／待機電源滿足啟動需求。
啟用 VRPower sequencer / platform logic 使能相關 VR；VR 以符合設計的啟動狀態建立 rail。
確認穩定VR 依自己的監控條件輸出 PGOOD，系統再按平台設計放行後續動作。
CPU 開始 SVIDCPU／SoC 在可通訊的階段向 VR 提出 VID，可能依負載與功耗狀態動態變更。
跟上一份 ATX 教學接起來：ATX PSU 的 PWR_OK、CPU VR Controller 的 PGOOD、SVID 的 ALERT# 是三個不同層次的訊號，不能把它們當成同一條線。

06 · DEBUG MINDSET

CPU 不開機，怎麼判斷是 SVID 還是 VR 出問題？

硬體工程師最有價值的是：先找出卡在哪一層，不要看到沒有 SVID 波形就直接判斷 CPU 壞了。

你看到什麼？優先查什麼？為什麼？
Vcore 完全沒有電壓VIN、VR 控制器供電、VR_EN、設定、短路、Fault不一定需要先有 SVID，VR 才開始工作
Vcore 有，但立刻掉電PGOOD、OCP/OVP/UVP、負載短路、時序可能是保護機制或後續 rail 的問題
SVID_CLK 沒活動CPU 啟動條件、reset、時鐘、平台狀態、SVID 接線／上拉CPU 可能尚未走到開始通訊的階段
SVID 有活動，電壓不符合預期控制器設定、對應 rail/address、load-line、feedback、Fault有通訊不代表調壓已成功或輸出一定等於 VID
電壓不穩或紋波過大負載暫態、功率級、電感／電容、layout、remote sense這是 VR 功率與控制迴路問題，不單是 SVID

量測順序

① VIN → ② Controller Bias/EN → ③ Vcore → ④ PGOOD/Fault → ⑤ SVID_CLK/DATA/ALERT# → ⑥ 輸出暫態/回授。

SVID 和 PMBus 不一樣

SVID：通常由 CPU 主導運行電壓管理。
PMBus：一些 VR Controller 額外提供，讓 BMC、EC 或測試工具進行設定、讀取電壓/電流/溫度與 Fault。不是每顆控制器都有。

同一顆 VR Controller 可能有兩條「管理通道」

兩者角色不同；有些 VR Controller 會同時支援 SVID 與 PMBus，但不是所有 Intel CPU Module 都把 PMBus 接給載板。
若要量 SVID：先確認 logic level、適用探棒、上拉電源及 bus speed。不要把 SVID 當一般 3.3V GPIO 隨便加上拉。實際訊號與電阻值必須看 CPU 與 VR Controller 的 datasheet。
07 · INTERVIEW

面試的時候，怎麼講得像有 CPU Platform 經驗？

30 秒中文版本

我理解 Intel CPU 的供電不只是把 12V 降成 1V。CPU 可以透過 SVID 跟 VR Controller 溝通目標電壓；VR Controller 再控制多相 Buck 電路，並利用回授維持穩定。系統開機時，我會先確認主電源、VR Enable、初始電壓及 PGOOD，再往 CPU Reset 和 SVID 通訊方向查。這樣可以更快判斷問題在供電、時序還是平台初始化。

如果面試官繼續問：「你以前用的是 D1713，真的有摸到 SVID 嗎？」

我的實際經驗是 CPU Module 與 Carrier Board 的系統整合。就 SVID 而言，我清楚它在 CPU 與 VR 之間的作用，也知道如何檢查訊號與 power sequence；但實際是否有直接修改 VR Controller 設定，會以我當時負責的工作範圍說明，不會把模組供應商完成的設計說成是我自己做的。
你的專案備註：Intel 官方列有 Xeon D-1713NT（Ice Lake、4 cores、45W）。你之前說「D1713」，有可能是此料號的簡稱，但應以實際 CPU 標記與 COM Express Module 料號再確認。這份教材是通用 Intel SVID/VR 原理，不能由 D1713 這個稱呼直接推定實際 VR Controller 型號、rail 與 SVID 接線。
08 · QUICK TEST

三題小測驗（點開看答案）

1. CPU 想降低 Vcore，SVID 跟 VR Controller 誰做什麼？

CPU 透過 SVID 發出對應的 VID 請求，VR Controller 解讀後控制功率級，讓 Vcore 依設計轉到新工作點；不是 SVID 線直接輸出電壓。

2. 沒看到 SVID_CLK，就能判斷 VR Controller 壞掉嗎？

不能。要先確認平台是否到達 SVID 通訊階段、CPU 啟動條件、主/待機 rails、reset 及 bus 連線。

3. VR Controller 和 PMBus 是同一樣東西嗎？

不是。VR Controller 是硬體控制器；PMBus 是部分控制器支援的管理通訊介面，常被 BMC/EC/測試工具使用。
