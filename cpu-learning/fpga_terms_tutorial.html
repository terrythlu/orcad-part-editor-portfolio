1. 先建立大地圖：FPGA 開發流程

先不要一開始就背名詞，先看它們在整個流程中的位置：

先用一句話記： 寫 Verilog → 綜合 → 擺放佈線 → 跑 timing → 下載到 FPGA → 用 ILA 抓內部訊號。CDC 是整個設計中一定要小心的「跨時脈」問題。

2. CDC 是什麼？（Clock Domain Crossing）

直覺理解

CDC 就是：訊號從一個 clock domain 跑到另一個 clock domain。

例如：

  • 模組 A 用 clk_a = 100 MHz
  • 模組 B 用 clk_b = 125 MHz
  • A 要把訊號送給 B

因為兩個時脈不同步，所以 B 取樣時，可能剛好碰到訊號切換中的不穩定區，這就可能產生 metastability（亞穩態）。

新鮮人要懂的重點

  • 單 bit 訊號：常用 2-FF synchronizer。
  • 多 bit 資料：不能隨便每一 bit 各自同步，常要用 handshake 或 async FIFO。
  • 問題本質：不是功能邏輯寫錯，而是時序與取樣關係有風險。
面試可以這樣說：
「CDC 是跨時脈域傳輸問題。若不同 clock domain 直接傳訊號，接收端可能出現 metastability。單 bit 通常用 2 級 FF 同步，多 bit 或資料流通常用 handshake 或 async FIFO。」

3. STA 是什麼？（Static Timing Analysis）

STA 是不需要真的把資料跑起來，就直接用數學和網路延遲模型，去分析電路 timing 有沒有過。

最常聽到的兩個 timing

  • Setup：資料要夠早到，不能太晚。
  • Hold：資料到達後，要撐一下，不能太快變。
一句話： STA 就是在確認「資料是否能在正確的時間被正確抓到」。
面試可以這樣說：
「STA 主要是檢查寄存器到寄存器之間的 timing path，確認 setup 與 hold 是否滿足。若 setup 違反，代表資料太慢；若 hold 違反，代表資料太快。」

4. WNS = -0.25 ns 代表什麼？

WNS = Worst Negative Slack，也就是「最差那一條 timing path 的 slack」。

Slack >= 0

Timing 過關。

代表資料在規定時間內到達。

Slack < 0

Timing 沒過。

代表資料晚到了。

WNS = -0.25 ns 的意思是：最差那條 path 比要求時間 晚了 0.25 ns。也就是說，目前設計存在 setup violation。

可以怎麼理解？

  • 要求 10.00 ns 內到
  • 結果實際 10.25 ns 才到
  • 所以 slack = -0.25 ns

看到 WNS 負值時，常見改善方向

  • 降低邏輯深度（logic 太深）
  • 加 pipeline
  • 改善 placement / routing
  • 修改 timing constraints
  • 確認 false path / multicycle path 是否正確
面試回答範例：
「WNS = -0.25 ns 代表最差 path 有 0.25 ns 的 setup violation。我會先看是 logic delay 還是 routing delay 造成，再決定是否加 pipeline、簡化邏輯，或檢查 constraints 是否合理。」

5. ILA / Logic Analyzer 是什麼？

ILA 常見於 Xilinx / AMD FPGA，意思是 Integrated Logic Analyzer。

你可以把它想成：放在 FPGA 裡面的示波器/邏輯分析儀。

  • 抓內部訊號
  • 設定 trigger 條件
  • 看狀態機有沒有跳對
  • 看資料流、valid/ready、error flag

Logic Analyzer 是比較大範圍的名詞，ILA 是 FPGA 裡面常用的內建版本。

面試可以這樣說：
「當模擬看起來正常，但板上行為不如預期時，我會插入 ILA 觀察內部訊號，例如 state、counter、handshake 訊號，透過 trigger 去抓問題發生前後的波形。」

6. Synthesis / Place & Route 是什麼？

Synthesis（綜合）

把你寫的 RTL（Verilog/VHDL）轉成實際硬體資源的表示方式，例如：

  • LUT
  • FF（Flip-Flop）
  • BRAM
  • DSP

簡單講：從程式描述 → 硬體邏輯結構

Place & Route（布局繞線）

綜合後，工具要決定：

  • 這些邏輯放在晶片哪個位置（Place）
  • 彼此之間怎麼接線（Route）

簡單講：把抽象邏輯真的放進晶片地圖裡

7. Verilog 跟 C 很像嗎？

像的地方：語法看起來有些像，例如 if、case、for、運算子、模組化。

不一樣的地方更重要：

項目CVerilog
本質軟體程式硬體描述語言（HDL）
執行方式大多是依序執行很多邏輯是同時並行運作
變數概念記憶體裡的資料常代表線路、暫存器、觸發器
時間概念通常不直接描述硬體時序時脈、edge、delay、timing 很重要
產出可執行程式可對應成邏輯電路

最關鍵的一句話

C 是在「告訴 CPU 要一步一步做什麼」；Verilog 是在「描述硬體本身要長什麼樣、如何在時脈下運作」。
// Verilog 範例：每個 clock 邊緣加 1
always @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    cnt <= 4'd0;
  else
    cnt <= cnt + 1'b1;
end
面試可以這樣說：
「我大學有寫過 Verilog，語法上和 C 有些相似，但概念上不同。C 偏向依序執行的軟體，Verilog 是描述硬體並行行為與時脈驅動邏輯，尤其對時序和寄存器概念要更敏感。」

8. FPLD / CPLD 目前有哪些架構？

這裡先釐清一下：

  • PLD = Programmable Logic Device，可程式化邏輯元件
  • FPLD = Field-Programmable Logic Device，現場可重複設定的邏輯元件，算是比較大的總稱
  • CPLD = Complex Programmable Logic Device
  • FPGA 也是 FPLD 家族的一種，但通常規模更大、更彈性

CPLD 的典型架構

  • Macrocell-based 架構
  • 由多個 Function Block / Logic Block 組成
  • 每個 block 裡有多個 macrocell
  • 透過可程式化 interconnect 連接

FPGA 的典型架構

  • LUT-based 邏輯陣列
  • 搭配 Flip-Flop
  • 外加 Block RAM、DSP、Clock 管理、IO Block
如果面試官問「目前有哪些架構」，新鮮人層級不用背很細的供應商家族名稱，知道 CPLD 偏 macrocell、FPGA 偏 LUT/FF + 豐富資源 就很夠用了。

9. 新鮮人面試怎麼講，才像真的懂？

你可以用這種口吻

「我大學時有接觸過 Verilog，知道它雖然語法有點像 C，但本質上是在描述硬體行為。對 FPGA flow 我理解是：先寫 RTL，之後做 synthesis，再進到 place & route，最後用 STA 檢查 timing。若 timing report 顯示 WNS 為負值，例如 -0.25 ns，代表最差路徑有 setup violation。若板上除錯時遇到模擬正常、實機異常，我知道可以用 ILA 去抓內部訊號。另外，若設計有跨時脈域，就要注意 CDC 問題，單 bit 一般會用 synchronizer，多 bit 可能用 async FIFO 或 handshake。」

這樣講會加分，因為它有三個特點

  1. 不是只背名詞，而是知道名詞在流程中的位置
  2. 知道每個問題的風險點，例如 CDC、timing violation
  3. 知道遇到問題時可以怎麼 debug

11. 給你的最後建議

  • 新鮮人不用裝得很資深，重點是講清楚邏輯。
  • 會比名詞更重要的是：你知道為什麼會出問題、出問題怎麼找。
  • 你可以不用說「我很熟」，你可以說：「我有學過、理解原理、願意快速補強」。這樣更自然。
最安全的面試策略：「我目前是新鮮人程度，但我能清楚說明整個 FPGA flow，知道 timing / CDC / debug 的基本觀念，也知道我下一步該怎麼學。」
